# cnubot 실험 설계 검토

실험을 새로 설계·시작하거나 표본·기간·지표·종료 기준을 바꾸기 전에 이 검토를 수행한다. 현재 저장소의 AGENTS.md와 실험 운영 문서를 먼저 읽는다.

## 모집 가능성부터 확인

- 운영 DB는 읽기 전용으로 집계한다. 개인 식별정보를 출력·저장하지 않는다. 개발자·QA·미리보기·빈 식별자는 제외한다.
- 해당 노출 위치의 **실제 노출 순사용자**를 7/14/28일 중복 제거해 비교한다. 학식 전체 사용자, 이벤트 건수, 일별 사용자 합계를 모집 규모로 쓰지 않는다. KST 기준 완결된 기간과 추출 시점을 기록한다.
- 요일·방학·휴일·정책 변경, 최근 주간 모집 편차와 재방문 포화를 검토한다. 모집 예상 범위를 제시하고 과거 최대치를 보장된 유입으로 쓰지 않는다.
- 동일 위치·문구·목적지에서 선행 노출 후 클릭한 사용자로 기준율을 계산한다. 기간 전체 누적 CTR과 개인별 24시간 CTR을 혼용하지 않는다. 계측 누락·extra 전달 미확인·정책 변경은 비교 한계로 명시한다.
- 기준율이 없으면 계측 점검 또는 탐색 실험으로 설계한다. 임의의 1%를 관측 기준율처럼 사용하지 않는다.

## 실행 가능한 계획과 검정력

- 모집 가능한 인원·기간을 먼저 정하고, 사업적으로 의미 있는 절대 차이(%p)를 정한다. 그 조건에서 검정력을 계산한다. 상대 상승률과 %p를 구분한다.
- 희소 클릭은 Fisher 정확검정 등 실제 분석 방법에 맞는 계산/시뮬레이션을 사용한다. 표본 공식만 믿지 말고 기준율·효과 여러 시나리오를 검토한다. 코드, 입력, 난수 시드/계산법을 남긴다.
- **운영 예상 인원**과 **통계적 필요 표본**을 분리한다. 부족하면 큰 효과 탐색·계측 검증·실험 통합/우선순위 조정 중 목적에 맞게 제안한다. 표본을 줄여 유의성 기준을 충족한 것처럼 표시하지 않는다.
- 시작 전에 배정 단위, 적격 조건, 주지표 하나, 관찰창, 모집/분석 종료 시각, 결측 처리, 안전성·SRM 기준, 성공/실패/판단 보류 규칙을 기록한다. 유의할 때까지 기간을 연장하거나 중간 결과로 조기 승자를 정하지 않는다.
- 목표 미달이나 넓은 신뢰구간은 ‘차이 없음’이 아니라 ‘판단 보류’로 보고한다. 탐색 결과에 확증 실험의 자동 승자 판정을 붙이지 않는다.

## 동시 실험과 진행 중 변경

- 실행 중인 모든 실험의 상태·배정·고정 정책 범위를 확인한다. 독립 배정은 상호작용 부재를 뜻하지 않는다. 같은 흐름의 버튼/상품 카드 테스트는 교차 노출과 상호작용 한계를 계획에 기록한다. 작은 표본을 무리하게 4개 군으로 쪼개 검정하지 않는다.
- 사용자가 요청한 동시 실행을 유지한다. 새 실험 때문에 기존 실험을 종료하거나 고정 정책 파일을 바꾸지 않는다. AGENTS.md의 배포 전후 무결성 검사와 공통 어드민 브라우저 검증을 수행한다.
- 진행 중 변경은 사후 개정으로 명시한다. 원래 계획·배정·시작 시각·원시 데이터·중단 이력을 보존하고 변경 시각/이유/새 종료 규칙을 기록한다. 사후 변경 결과는 탐색으로 해석한다.

## 완료 조건

검토 결과는 저장소 문서에 기간·적격 인원·기준율·계측 한계·검정력·최종 실행계획·동시 실험 영향을 남긴다. 코드/운영 DB/어드민의 목표와 종료 규칙이 같은지 확인한다. 설계만 완료했는지 운영 적용까지 완료했는지 구분한다.

이 저장소의 버튼 집계 예시는 `backend/app/jobs/review_menu_button_history.py`, 설계 개정 사례는 `docs/menu-button-experiment-design.md`를 참고한다. 다른 노출 위치에는 이벤트/적격 조건을 맞춰 다시 계산한다. 과거 사례의 숫자를 새 실험에 복사하지 않는다.
