# 학교혜택 수집과 카카오 연결

## 제공 정보

학교혜택은 최신·마감임박 및 장학금·교육·해외교류·인턴창업·교내채용·학사정보·행사로 탐색한다. 모집 공고는 한 번에 5개, 신청 마감/D-day와 확인된 혜택·지원 대상의 일부 요약을 표시한다. 완전한 조건·예외와 첨부는 `공고 보기` 링크에서 확인한다. 게시일을 마감일로 사용하지 않는다. 명시된 마감일이 없거나 회차별 마감이 불명확하면 미확인 안내를 제공한다.

해외교류 출처는 `https://cnuint.cnu.ac.kr/cnuint/notice/recruit.do`다. 목록 링크·게시일과 HTML 본문에서 명시한 신청기간을 수집한다. PDF/HWP/이미지 첨부만 있는 조건은 자동 해석하지 않는다. 일반 학사정보를 해외교류로 분류하지 않는다.

## 운영 적용

코드 반영 후 기존 backend 이미지와 새 benefits-collector 이미지를 빌드하고 함께 실행한다.

```sh
docker compose up -d --build backend benefits-collector
```

backend 시작 시 `benefits_browse_states` 테이블·만료 인덱스를 생성한다. 사용자 ID 원문 대신 해시와 30분짜리 목록 스냅샷을 보관한다. 만료 목록은 조회 시 정리하며, DB가 없으면 분야별 첫 페이지와 공식 링크를 제공하고 페이지 이동은 숨긴다.

두 컨테이너는 `BENEFITS_DATA_PATH`가 지정한 공유 볼륨 파일을 사용한다. 경로가 지정되지 않은 개발 환경에서는 패키지의 `static/data/benefits.json`을 사용한다. 운영 공유 파일 생성 전에는 새 형식의 패키지 스냅샷을 사용한다. 잘못된 마감일이 포함된 구형 스냅샷은 사용하지 않는다.

collector는 시작 시 수집 필요 여부를 확인하고, 소스별 정상 수집 후 6시간이 지나면 갱신한다. 실패·상세 누락은 15분 간격으로 재시도한다. 기본 수집 범위는 각 게시판의 3페이지이며 최근 120일 이내 기존 수집 공고도 보관한다. 마감이 확인되지 않은 공고의 표시 범위는 최근 90일이다. 최근 페이지 밖에 처음 게시된 모든 장기 모집 공고를 포괄하는 기능은 아니다.

수동 확인은 실행 중인 collector에서 수행한다. 같은 파일에 쓰는 수집기를 동시에 실행하지 않는다.

```sh
docker compose logs --tail 20 benefits-collector
```

전체 소스 실패 시 마지막 파일을 유지한다. 부분 실패는 해당 소스의 마지막 정상 목록을 유지한다. 평소 목록은 분야·현재 페이지·전체 페이지 한 줄만 표시하며 수집 시각과 반복 원문 안내는 생략한다. 24시간 이상 지연되면 해당 분야(전체 최신은 가장 오래된 소스)의 마지막 성공 날짜와 짧은 안내를 표시한다. 부분 실패는 갱신 중 안내 한 줄만 표시한다. 첫 진입 소개는 출처와 분야 더 보기 이용 방법을 두 줄로 제공한다.

수집 재시도는 최근 6시간 내 정상 수집된 게시판을 재요청하지 않고 실패·지연된 게시판만 갱신한다. 네트워크 연결 오류·타임아웃은 해당 요청을 1초 후 한 번 더 시도한다. 처음 공유 데이터를 만드는 중 실패한 분야는 검증된 패키지 목록도 보존한다. `--once` 수동 수집은 모든 분야를 다시 확인한다.

## 카카오 관리자 등록

새 스킬 URL을 만들 필요는 없다. 다음 **네 발화**를 기존 스킬에 추가한다. 구현 후 등록 가능하며 배포·관리자 등록·실기기 렌더링은 별도로 확인한다.

| 기존 POST 경로 | 추가할 정확한 messageText | 버튼 label |
|---|---|---|
| `/benefits/list` | `학교혜택 학사정보` | 학사정보 |
| `/benefits/list` | `학교혜택 행사` | 행사 |
| `/benefits/list` | `학교혜택 분야` | 분야 더 보기 |
| `/benefits/page` | `학교혜택 이전` | ◀️ |

URL 예시: `https://example.com/benefits/list`, `https://example.com/benefits/page`. 전체 기존 발화와 POST 경로는 [카카오 등록표](kakao-message-routing.md#학교혜택-매핑)를 따른다. 해외교류는 기존 `학교혜택 해외교류` → `/benefits/list` 등록을 그대로 사용한다. 직접 입력과 버튼의 messageText는 이 등록표와 일치해야 한다. 페이지 이동은 요청의 사용자 ID를 사용하며 `extra` 전달을 전제로 하지 않는다.

## 간결한 탐색 버튼

첫 화면은 마감임박·분야 더 보기와 필요한 ▶️까지 최대 3개다. 이후 목록은 필요한 다음/이전·최신 공고(최신 화면에서는 마감임박)·분야 더 보기까지 최대 4개다. 전체 분야는 분야 더 보기에서 혜택·배움 / 진로·채용 / 학교 소식 3개 카드로 묶어 한 말풍선 안에서 좌우로 넘겨 선택한다. 이 메뉴의 퀵리플라이는 최신 공고·마감임박 2개만 표시한다. 메뉴 진입 자체로 현재 목록과 페이지를 초기화하지 않는다. 이번 간결화의 신규 발화는 `학교혜택 분야` → 기존 `POST https://example.com/benefits/list`이며 구현 후 등록 가능하다. 새 스킬 URL은 필요 없고 운영 배포·카카오 등록·실기기 확인은 별도다.

분야 메뉴는 세로로 나열된 개별 말풍선 대신 가로 textCard 캐러셀로 제공한다. 기존 `POST /benefits/list`와 정확한 발화 `학교혜택 분야`를 그대로 사용하며, 구현 완료 후 기존 등록 사용 가능, 이 표시 변경에 따른 추가 카카오 등록은 없다.

학교혜택 페이지 이동 버튼 표시명은 이전 `◀️`, 다음 `▶️`다. 함께 표시할 때는 이전·다음 순서로 배치한다. 실제 전달하는 messageText는 `학교혜택 이전`, `학교혜택 다음`이며 기존 `POST /benefits/page` 등록을 유지한다. 구현 완료 후 기존 등록 사용 가능, 이 표시 변경에 따른 추가 카카오 등록은 없다.
