# 학교 주변 맛집 운영

구현 기능: 카카오 Local 음식점 발견·공개 장소 메뉴/집계 평점 수집, 궁동·어은동·죽동 선택, 랜덤 한 곳과 3개 예산 구간의 최대 3곳 추천, 7일 노출 우선순위·재추천, 카카오 평점 필터, 서명된 지도 이동·이벤트, 관리자 편집·미리보기.

허위 메뉴·가격·평점을 샘플로 배포하지 않는다. `restaurant-collector`의 최초 수집이 끝나면 실제 공개 데이터로 추천이 시작된다. 수집 전·실패로 유효한 메뉴가 없을 때만 준비 중 안내다. 공개된 메뉴 등록 가격이며 현장 현재 가격을 보장하지 않는다.

## 등록 및 공개

1. `docker compose up -d --build backend restaurant-collector`로 코드를 배포한다. backend 시작 시 추가 DB 테이블을 생성하고 수집 컨테이너가 최초 수집을 시작한다. 기존 사용자 작업과 운영 데이터를 유지한다.
2. 기존 관리자 인증으로 `https://example.com/admin/restaurants`를 연다.
3. 자동 수집된 목록을 확인한다. 수집은 지역별 `음식점` 3페이지와 `한식`·`일식`·`중식`·`양식`·`분식` 각 최대 2페이지의 Local 후보를 조회한다. 동일 장소 ID·대전 유성구 해당 동 주소를 검증한 공개 메뉴와 집계 평점만 저장하며 목록 상한은 500곳이다. 관리자 장소 검색은 별도의 일시적 조회다.
4. 필요하면 식당·메뉴를 수정한다. `수집 결과로 자동 갱신` 체크를 해제하면 수동 관리 항목으로 전환되어 수집기가 덮어쓰지 않는다. 공개 해제한 자동 항목도 재수집으로 다시 공개하지 않는다. 직접 등록할 때는 확인 출처·가격·인원을 입력한다.
5. 추천 미리보기로 9개 지역·예산 조합의 후보 수와 카드를 확인한다. 미리보기는 실제 사용자 탐색·이벤트를 기록하지 않는다. 공개할 조합마다 최소 6곳 확보를 권장하되, 1~2곳이면 실제 수만 표시한다.
6. [정확한 카카오 등록표](kakao-message-routing.md#학교-주변-맛집)의 20개 발화를 해당 POST 경로에 등록한다. 별점 데이터가 아직 없어도 별점 경로를 미리 등록할 수 있지만 실제 별점 기능 사용은 아래 조건 충족 후 가능하다.
7. 비공개 운영 설정에 `RESTAURANTS_ENABLED=true`를 설정하고 backend를 재생성한다. 학식 시간표·요일 메뉴에 맛집 진입 버튼이 표시된다. 실제 카카오 메시지 연결을 확인한다.

예산은 등록 메뉴 비용 10,000원 미만 / 10,000~19,999원 / 20,000원 이상이다. 자동 메뉴는 정확한 숫자 가격이 있는 식사 항목만 사용하며 음료·주류·추가 토핑·어린이·중량 단가·시가·최소/공유 주문 조건은 제외한다. 메뉴가 식사 항목인지 알 수 없으면 포함하지 않는다. 수동 세트는 확인한 인원으로 나누고 원 미만을 올림한다. 조회/확인 후 30일이 지난 메뉴는 제외한다. 가격 조회일·원문 메뉴 등록일·평점 조회 시각은 카탈로그에 보관하고 카드에서는 생략한다. 카드에는 메뉴·가격, 별점·리뷰 수만 우선 표시한다. 원문 메뉴 등록 후 180일을 초과한 가격에는 방문 전 확인 안내 한 줄을 표시한다. 상세 링크 버튼은 `메뉴·후기 보기`다.

기본 추천과 랜덤 한 곳은 **카카오맵 별점 3.0 이상·평가 10개 이상**인 식당만 사용한다. 평점은 확인 후 7일 이내여야 하며, 미확인·오래된 평점은 추천하지 않는다. 3.5 / 4.0 / 4.5 필터는 이 기본 기준에 추가로 적용된다. 평점 사용을 꺼둔 경우 기본 추천도 빈 결과가 된다. 수집 목록에는 기준 미달 식당도 보관해 재수집 시 평가 수가 변하면 다시 판별한다.

## 자동 갱신

수집 성공 후 6시간마다 갱신하며 부분 실패·실패는 30분 간격으로 재시도한다. 한 장소씩 조회하고 요청 사이 0.5초를 둔다. 로그인·차단·인증 우회, 리뷰 본문·작성자·사진의 저장, 원본 응답 전체 보관은 하지 않는다. 공개 웹 응답은 공식 Local API의 보장된 규격이 아니므로 변경 시 수집 실패로 처리한다.

전체 수집 실패는 목록을 교체하지 않는다. 부분 실패는 해당 장소·지역의 마지막 목록을 유지한다. 정상 공개 페이지에서 비활성 또는 메뉴가 없어졌다고 확인되면 자동 관리 항목만 제거한다. 검색에서 발견되지 않은 식당을 바로 폐업으로 추정하지 않는다. 갱신 시 최신 파일을 잠근 뒤 병합해 수집 중 관리자가 편집한 수동 항목·공개 해제를 보존한다.

수집 상태는 `restaurants_collection.json`에 성공 시각·지역별 후보/수집/실패 수만 저장한다. 수동 실행은 `docker compose exec -T backend python -m app.jobs.collect_restaurants --once`다. 수집 잠금으로 중복 실행을 막는다. 가격은 공개 페이지의 등록 정보이며 오래된 메뉴 등록일을 수집일로 바꾸지 않는다.

## 별점 데이터

카카오 공식 장소 검색 API는 별점·평가 수를 제공하지 않는다. 사용자의 크롤링 요청에 따라 공개 장소 페이지의 `score_set.average_score`와 `review_count`만 수집한다. 처음 집계 평점이 확보되면 필터를 활성화하고 출처를 기록한다. 관리자가 이후 별점 사용을 해제하면 자동 수집으로 다시 활성화하지 않는다. 리뷰 작성자나 개별 리뷰는 보관하지 않는다.

평점은 카카오 출처, 0~5의 소수점 한 자리, 양수 평가 수로 검증한다. 7일을 초과한 평점은 표시 및 최소 평점 필터에서 제외한다. 최소 평점 3.5 / 4.0 / 4.5를 선택할 수 있고 `전체`는 별점 제한을 해제한다. 예산이나 별점 기준은 후보가 부족해도 자동 완화하지 않는다. 별점 사용 설정만 켠다고 검색 API에서 별점을 받는 것은 아니다.

수동 입력은 `origin=manual`, 공개 수집은 `origin=kakao_public`으로 구분한다. 수집 항목은 식당·메뉴·숫자 가격·메뉴 원문 등록일·집계 평점·평가 수·조회 시각·출처다.

## 저장·장애·계측

- 목록: 공유 메뉴 볼륨의 `restaurants.json`. `RESTAURANTS_DATA_PATH`로 변경 가능하다. 프로세스 간 파일 잠금·원자 교체·버전 검사로 충돌을 막는다. 손상된 파일은 자동으로 빈 목록으로 덮어쓰지 않는다. 관리자 읽기는 오류로 알리고 사용자 추천은 준비 중 안내로 처리한다.
- 탐색: PostgreSQL의 `restaurant_browse_states`. 30분 미사용 시 선택이 만료되고 노출 이력은 7일 유지한다. 사용자별 트랜잭션 잠금으로 동시 재추천을 직렬 처리한다. 원시 사용자 ID 대신 해시만 보관한다. 재추천은 현재 세션 조건을 사용한다.
- DB 실패·사용자 ID 없음: 기본 추천과 지역·예산 선택은 가능하다. 예산 발화가 지역까지 포함하므로 세션 없이도 추천 가능하다. 재추천·별점 선택은 숨긴다.
- 지도 링크: HTTPS `SERVER_URL`과 `RESTAURANTS_TRACKING_SECRET` 또는 기존 `PROMOTION_TRACKING_SECRET`을 사용한다. 조건이 충족되지 않으면 직접 카카오맵 링크를 제공하며 클릭을 계측했다고 보고하지 않는다. 추적 비밀값은 별도 공개 파일에 기록하지 않는다.
- 이벤트: 별도 `restaurant_events`에 `entry`, `recommendation`, `map_click`을 저장한다. 추천 이벤트에는 세션·지역·예산·별점·실제 노출 식당·빈 결과·재추천 여부를 기록한다. 클릭 링크는 7일 만료, HMAC 서명 검증, 동일 링크 중복 클릭 제외, 현재 공개 식당의 카카오맵 URL만 허용한다. 조회 실패도 지도 이동을 막지 않는다.

진입 발화는 버튼 입력과 직접 입력이 같으므로 학식 버튼에서 들어왔는지 추정하지 않는다. 지도 이동률·선택까지 걸린 시간·조건별 빈 결과율·재추천 횟수·7일 재사용은 이벤트로 분석할 수 있다. 실제 방문·식사 완료나 자동화된 링크 조회 여부는 이 이벤트만으로 확인할 수 없다. 기존 상품 실험 이벤트와 섞지 않는다.

## 관리자 경로

| 경로 | 용도 |
|---|---|
| `GET /admin/restaurants` | 식당 편집 화면 |
| `GET /admin/restaurants/catalog` | 인증된 목록 조회 |
| `PUT /admin/restaurants/catalog` | 검증된 전체 목록 저장 |
| `POST /admin/restaurants/search` | 일시적 카카오 음식점 검색 |
| `POST /admin/restaurants/preview` | 저장 전 추천 미리보기 |

전체 관리자 경로는 기존 Basic 인증이 필요하다. 저장·검색·미리보기는 `X-Restaurants-Editor: 1`도 요구한다. 검색 키는 Docker Compose에서 `KAKAO_REST_API_KEY`를 backend에 전달하며 값은 로그·응답에 출력하지 않는다. 관리자 API는 카카오 사용자 흐름이나 스킬 등록 대상이 아니다.

## 검증

`python -m unittest tests.test_restaurants tests.test_restaurant_collection`로 가격 경계·수집 파싱·개인정보 제외·부분 실패 보존·별점 조건·등록 발화·동시 재추천·저장 충돌·인증·서명 링크를 검증한다. 테스트 식당은 가상 픽스처로 실제 운영 목록에 저장하지 않는다.
