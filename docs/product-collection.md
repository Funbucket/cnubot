# 상품 배치 수집

`product-collector` Compose 서비스가 KST 00:05 / 06:05 / 12:05 / 18:05에 수집한다. 중단 후 재시작하면 현재 시간대의 미실행 작업을 수행한다. 파일 잠금과 실행 이력을 공유하므로 같은 시간대에 중복 수집하지 않는다.

- 카테고리, 베스트 100개, 오늘 특가 30개, 기획전별 최대 18개 카테고리에서 20개씩 수집한다. 카테고리가 겹치면 조회를 합친다. 전체 카탈로그를 무제한 순회하지 않는다.
- 목록 응답에 있는 상품명·가격·이미지·품절 정보를 저장해 상세 조회에도 사용한다. 추가 상세 API 조회는 하지 않는다.
- 표시 가능한 상품의 제휴 링크를 미리 발급해 저장하고 이후 수집에서 재사용한다.
- 회당 상품 조회 예약량 최대 850개, 하루 4회 최대 3,400개다. 별도로 하루 6,000개 보수적 예약 상한을 두고 호출 전에 디스크에 기록한다. 새 링크는 중복 상품을 제외한 후보 수 이내다. 다른 클라이언트에서 사용한 계정 할당량은 이 수치에 포함되지 않는다.
- 외부 요청은 직렬화하고 요청 사이 최소 0.12초를 둔다. 실패한 작업은 다음 시간대에 재시도하며, 일일 한도 초과는 다음 KST 날짜까지 중단한다.
- 데이터는 `MENU_DATA_DIR` 아래 `product_snapshot.json`, 실행·한도 이력은 `product_collection_state.json`에 원자적으로 저장한다. 재시작에도 유지하며 Git에 넣지 않는다.
- 수집 중 오류가 나면 이전에 성공한 상품 목록을 유지한다. 발급 완료 링크는 별도로 보존한다. 정상적으로 받은 빈 목록은 빈 상태로 갱신한다.
- 일반 상품은 마지막 수집으로부터 최대 48시간 사용한다. 오늘 특가는 수집한 KST 날짜가 지나거나 `endAt`이 지나면 제외한다. 배치 사이 가격·품절 변경은 즉시 반영되지 않는다.
- 카카오 목록·새로고침·학식 인라인 카드의 상품 조회와 링크 조회는 저장소만 사용한다. 메모리 후보 캐시 때문에 새 배치 반영은 최대 약 5분 지연될 수 있다.
- 사용자·기획전별 최근 노출 이력으로 미노출 상품을 우선 선택하고, 소진 후 오래전에 노출한 상품부터 순환한다. 상품 종류 다양성 제한은 유지한다. 적격 후보가 적으면 일부 상품이 반복되거나 6개 미만일 수 있다.
- 첫 수집에 성공하기 전에는 먹거리·꿀템의 기존 등록 상품을 대체 사용한다. 오늘 특가가 없거나 조회·링크 처리에 실패하면 저장된 할인 상품으로 대체 추천한다.

실행 및 확인:

```sh
docker compose up -d --build backend product-collector
docker compose logs --tail=20 product-collector
```

같은 시간대 중복 실행과 일일 한도 차단을 유지하는 수동 실행:

```sh
docker compose run --rm product-collector --once
```

카카오 POST 경로와 발화는 기존 등록표 그대로다. 새로운 카카오 등록은 필요 없다.

## 어드민 현황 확인

`/admin/recommendations`의 상단 **자동 추천 · 배치 수집 현황**에서 마지막 수집 결과, 마지막 시작·성공 시각, 다음 예정 시각, 전체 저장 상품 수와 기획전별 사용 가능한 후보 수를 확인한다. 자동 추천·대체 등록 상품·고정 모드·빈 목록을 구분한다. 저장된 운영 설정을 기준으로 하며 편집 중인 미저장 설정은 반영하지 않는다.

관리자 인증이 필요한 `GET /admin/promotion-settings/collection-status`에서 읽기 전용 요약을 제공한다. 화면은 1분마다 갱신하며 **상태 새로고침**으로 즉시 확인할 수 있다. 상태 조회는 Toss API를 호출하거나 상품 노출을 기록하지 않는다. 표시하는 예약량은 로컬 배치 기록이며 Toss 계정의 실제 사용량·잔여 한도를 뜻하지 않는다. 예정 시각 및 실행 시작 기록은 배치 프로세스의 생존 상태를 보장하지 않는다.

## 오늘 특가 대체 추천

오늘 특가가 비거나 표시 가능한 특가가 없으면 같은 POST `/promotions/collections/today-deals`와 발화 `오늘 특가`에서 할인율 높은 상품을 최대 6개 제공한다. 기존 경로와 발화는 구현 완료 상태이며 추가 카카오 등록은 필요 없다. 응답에 “오늘 특가 대신 할인율 높은 상품을 모았어요 🛍️”를 표시하고, 학식 인라인 카드에도 “할인율 높은 추천 상품”을 표시한다.

대체 후보는 저장된 식품·생활용품 상품 중 5만원 이하, 할인율 40% 이상을 우선하며 부족하면 30% 이상까지 확대한다. API 할인율은 가격으로 계산한 할인율을 넘지 않게 제한한다. 일반 상품의 48시간 유효기간, 품절·만료 제외, 학생 제외 기준을 적용하고 저장된 제휴 링크가 있는 상품만 사용한다. 같은 품목은 하나, 같은 그룹은 기본 2개·부족하면 3개까지 표시한다. 각 할인 구간에서 미노출 상품 우선, 소진 후 오래된 노출 순으로 순환하고 할인율을 우선 비교한다. 새로고침은 기존 `오늘 특가` 발화를 사용하며 요청 중 외부 상품 API를 호출하지 않는다. 대체 후보도 없으면 준비 중 안내를 표시한다. 노출·클릭에는 `selection_mode=high_discount_fallback`을 기록하고 어드민에도 대체 추천 상태를 표시한다.
