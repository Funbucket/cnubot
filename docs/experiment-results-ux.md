# 종료된 실험 결과 검토

종료된 버튼 실험에서도 SRM 실패 외에는 항상 ‘판단 대기’를 표시하던 요약을 수정한다. 모집 종료, 통계적 관측, 품질 검토, 채택 결정은 서로 다른 사실이며 하나의 대기/통과 배지로 합치지 않는다. 이 변경은 Vercel 관리자 표시 계층에 적용하며 실험 상태·계산·원래 계획·판정 게이트·감사 기록을 변경하지 않는다.

| 구분 | 표시 원칙 |
|---|---|
| 실행 상태 | 완료·결정 기록·운영상 중단을 원본 상태대로 표시한다. 종료 후 수집 중이라는 안내를 사용하지 않는다. |
| 관측 결과 | 실제 군별 이름·클릭 사용자/분모·전환율·B−A 절대 차이(%p)·기존 95% 신뢰구간·검정 p값을 표시한다. 상대 변화는 별도 단위로 구분한다. |
| 통계 해석 | 구간이 0을 포함하면 방향 불확실로 표시하며 차이 없음·동등성으로 해석하지 않는다. 분모 0·누락·잘못된 구간에는 효과를 만들지 않는다. p값은 승리 확률로 표현하지 않는다. |
| 품질 | SRM 이상 미검출과 클릭 수집 완전성을 분리한다. 운영 확인 미기록은 ‘계측 확인 제한’, 실제 실패는 ‘품질 문제 있음’으로 표시하고 근거를 개별 항목으로 제공한다. |
| 제품 결정 | 기록된 결정·근거·검토 분석 ID·후속 실험 링크를 제공한다. 관측 방향만으로 채택 결정을 만들지 않는다. |
| 탐색 실험 | 사후 계획 개정과 자동 승자 판정 대상이 아님을 명시한다. 폐기된 원래 표본 목표를 종료 후 충족해야 할 조건처럼 표시하지 않는다. |
| 중단된 A/A | 기본 계측 부분 승인과 정식 전체 통과를 구분한다. 확인된 항목과 미확인 항목, 중단·오류 기록을 유지한다. |

버튼 실험은 실제 시작~종료 구간의 누적 조회 집계, 카드 실험은 저장된 분석 ID·데이터 기준 시각을 명시한다. 종료 기록 시각을 예정 마감으로 대체하지 않는다. 종료 보고서와 공통 목록의 품질 요약을 일치시키며 모바일에서는 긴 품질 상태를 독립 행에 표시한다. 일별 추이·세그먼트·추가 지표를 근거 없이 생성하지 않는다.

기본 결과 화면에는 쉬운 말로 쓴 관측 결과 한 문장, 군별 비교표, 신뢰구간, 짧은 품질 주의사항만 제공한다. 기간·결정 기록과 분모·통계 근거는 기본적으로 접어 두며, 참여자 요약·가설·상세 해석은 진행 현황과 품질 탭에서 확인한다. 설명을 반복하는 별도 요약 패널이나 동일 수치의 중복 KPI를 결과표 위에 쌓지 않는다. 실제 제품의 비교표·상세 팝업 구조를 참고하며 문서의 설명 문장을 기본 화면에 그대로 옮기지 않는다.

## 참고한 제품

- [Statsig 결과 읽기](https://docs.statsig.com/experiments/interpreting-results/read-results): 주요 지표 비교표, 효과와 신뢰구간, 노출 규모를 함께 검토하는 구조.
- [Statsig 종료와 결정 보류](https://docs.statsig.com/experiments/ending/conclude-experiment-defer-decision): 운영 종료와 제품 채택 결정을 분리하는 상태 설명.
- [Optimizely 결과 페이지](https://docs.optimizely.com/experimentation-strategy/docs/p_zW-optimizely-experiment-results-page): 실험 상태·건강성·주요 지표·데이터 시각을 구분하는 구성.
- [Amplitude 분석 화면](https://amplitude.com/docs/feature-experiment/analysis-view): 군별 전환값 아래 분자와 분모를 함께 표시하고 효과 크기와 불확실성을 확인하는 구조.

각 제품의 통계 엔진이나 자동 승자 판정을 도입한 것은 아니다. 이 프로젝트의 기존 Fisher 정확검정·Newcombe-Wilson 구간과 고정 설계를 그대로 표시한다.

## 검증

`apps/insights/tests/experiment-report.test.ts`는 종료된 탐색 실험, SRM 실패, 누락/분모 0/잘못된 구간, 0을 포함한 구간, 후속 결정·복구, 중단된 A/A 부분 승인을 검증한다. `scripts/verify_experiment_detail_ux.cjs`와 공통 `scripts/verify_experiment_admin.cjs`는 실제 API 수치·종료 요약·품질 근거·후속 링크·직접 새로고침·왕복·모바일을 읽기 전용으로 검증한다. 실행 중인 실험의 상태를 변경하지 않는다.
