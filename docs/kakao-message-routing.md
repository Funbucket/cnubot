# 카카오 메시지 → POST API 등록 규약

2026-09-11 사용자 확정 사항. 이 문서는 설계 및 수동 카카오 등록의 기준이다.

## 동작

사용자 입력 또는 버튼 messageText → 카카오 관리자에 등록한 발화/블록 → 연결한 POST 스킬 URL → KakaoRequest의 userRequest.utterance 해석 → 카카오 응답 JSON.

API를 구현하는 것과 카카오에 발화를 등록하는 것은 별도 작업이다. 등록은 사용자가 수행한다. 새 API 인계 시 POST 경로, 정확한 발화 목록, 구현 상태를 반드시 제공한다. 등록 시 비공개 운영 설정의 서버 기본 주소에 아래 경로를 붙인다. 이 저장소는 public이므로 실제 운영 IP·호스트·접속 정보는 기록하지 않는다. 전체 URL 예시가 필요하면 `https://example.com`을 사용한다.

## 메뉴 빈자리 먹거리 카드

### 개발자 전용 3개 상품 미리보기

`PROMOTION_BUNDLE_PREVIEW_ENABLED=true`이고 요청 사용자 ID가 비공개 환경 설정의 `DEVELOPER_ID`와 일치할 때만 새 UI를 표시한다. 기본값은 false이며 다른 사용자에게는 기존 응답을 유지한다. 실제 사용자 ID를 저장소에 넣지 않는다.

- 학식의 기존 상품 슬롯에 간편식·간식/음료·생활용품을 최대 3개 가로 commerceCard 캐러셀로 표시한다. 출력은 한 슬롯이며 기존 사용자별 KST 하루 1회 제한과 기숙사 아침 복원 기능을 유지한다. 적격 후보가 적으면 1~2개를 표시하고 후보가 없으면 기존 추천으로 돌아간다.
- `오늘 특가`·먹거리·꿀템 직접 진입과 새로고침은 개발자 계정에도 기존 최대 6개 목록을 유지한다. 3개 묶음은 학식의 기존 상품 슬롯에만 적용한다.
- 상품별 표시 가격 1만원 이하, 기본 할인·수량 조건, 학생 제외 기준, 저장 상품의 유효기간과 제휴 링크를 적용한다. 새 상품 API나 링크 발급을 요청 중 호출하지 않는다. 제휴임을 카드에 표시하며 배송비 포함 최종 가격을 보장하지 않는다.
- `특가 바로가기`는 기존 추적 webLink다. `먹거리 더 보기` → `자취생 먹을거 핫딜`, `꿀템 더 보기` → `자취생 꿀템`는 기존 POST 등록을 그대로 사용한다. **구현 완료 후에도 신규 발화 등록은 필요 없으며 실기기 렌더링은 별도 확인한다.**
- 자동 묶음은 일일 슬롯을 원자적으로 한 번 확보한 후 모든 상품 노출을 한 트랜잭션으로 기록한다. 묶음의 selection_mode는 `student_bundle_preview`다. 정식 무작위 A/B 실험을 시작하는 기능은 아니다.

- 빈자리 자동 상품 카드는 사용자별 KST 기준 하루 최대 1회만 노출한다. 당일 실제 카드 노출 기록이 있으면 이후 학식 조회에서는 카드를 생략한다. 사용자가 직접 `오늘 특가`·먹거리·꿀템 기획전을 여는 흐름은 이 제한을 받지 않는다. 빈자리는 오늘 특가·food·living 기획전을 순환한다. 고정 모드는 표시 가능한 활성 상품을 사용자별 노출 이력에 따라 선택한다. 기획전 조회 실패 또는 표시 가능한 상품이 없으면 다음 기획전을 시도하며, 모든 기획전에서 상품을 구하지 못했을 때만 카드를 생략한다. 노출 기록 저장소를 확인할 수 없을 때도 반복 노출 방지를 위해 카드를 생략한다.
- 자동 모드는 배치로 저장한 카테고리·상품 정보에 기존 가격·할인·수량 조건을 적용한다. 카카오 요청에서 상품 API나 링크 발급 API를 호출하지 않는다.
- 빈자리 상품 카드에는 상품 버튼과 현재 기획전 더 보기 버튼만 표시한다. 오늘 특가 상품은 `특가 더 보기` → `오늘 특가`, food 상품은 `먹거리 더 보기` → `자취생 먹을거 핫딜`, living 상품은 `꿀템 더 보기` → `자취생 꿀템`으로 연결한다. 빈자리 상품 선택 순서는 `오늘 특가` 1개 → food 1개 → living 1개이며, 각 상품은 사용자별 최근 노출 이력을 기준으로 순환한다. 기본 food 발화는 `자취생 먹을거 핫딜`이며 아래 food POST 경로에 매핑한다.
- 카드가 응답에 실제 포함된 경우만 노출 기록을 남긴다. 노출·상품 클릭에 collection_id, selection_mode, settings_revision을 보관한다. 인사이트는 배포 후 이 정보가 기록된 데이터만 기획전별 집계한다.
- 먹거리 더 보기의 클릭 위치는 카카오 action.clientExtra/action.extra가 전달된 경우에만 구분한다. 누락된 위치를 추정하지 않으며 URL 기반 기획전 정보는 유지한다. 실제 카카오 전달 여부는 운영에서 별도 확인한다.

## 상품 기획전 매핑

자동 추천은 KST 00:05 / 06:05 / 12:05 / 18:05 배치 수집 결과를 사용한다. 후보·가격·이미지·제휴 링크와 실행 이력을 디스크에 저장하므로 서버 재시작에도 유지된다. 새로고침은 저장된 후보에서 최대 6개를 선택하며, 사용자·기획전별 미노출 우선 → 모두 노출한 뒤 오래된 노출 순으로 계속 순환한다. 후보가 충분하지 않거나 다양성 조건에 걸리면 일부 반복 또는 6개 미만 응답이 가능하다. 수집 실패는 마지막 성공 목록을 유지하며 일반 상품은 최대 48시간, 오늘 특가는 수집 당일과 만료 시각까지만 사용한다. 구현 및 운영 방법은 [상품 배치 수집](product-collection.md)을 참조한다. 아래 POST 경로와 발화는 구현 완료 상태이며 기존 등록을 그대로 사용할 수 있다.

먹거리·꿀템 목록의 자동 추천 조회가 실패하거나 결과가 비면 해당 기획전에 등록된 활성 상품 링크를 표시한다. 미노출 상품을 먼저 보여주고 모두 노출했으면 오래전에 노출한 상품부터 다시 순환한다. 가격을 확인할 수 없는 대체 상품은 가격 없이 상품명·이미지·링크 카드로 표시한다. 등록된 활성 상품도 없는 경우에는 준비 중 안내를 유지한다. 기존 POST 경로와 발화는 그대로 사용하며 추가 등록은 필요 없다.

| POST 경로 | 카카오에 등록할 정확한 발화 | 용도 |
|---|---|---|
| `/promotions/collections/food` | `자취생 먹을거 핫딜` | 식품·간식·음료 기획전 |
| `/promotions/collections/living` | `자취생 꿀템` | 생활용품과 추천 상품 혼합 기획전 |
| `/promotions/collections/today-deals` | `오늘 특가` | Sharelink 하루특가 상품 목록 |

학식 스케줄 첫 응답에는 `⚡️ 자취생 특가` → `자취생 먹을거 핫딜` 퀵리플라이 하나만 표시한다. 2026-10-13에 버튼 수를 줄이려는 사용자 요청과 최근 관측 CTR을 근거로 정리했다. 오늘 특가·꿀템은 기존 발화와 기획전 내 탐색으로 계속 조회할 수 있다. food 결과는 `🔥 오늘 특가` → `자취생 꿀템` → `새로고침` 순서로 표시하며, living 결과는 `🔥 오늘 특가` → `🍱 자취생 먹을거` → `새로고침` 순서로 표시한다. 오늘 특가 응답은 `🍱 자취생 먹을거` → `자취생 꿀템` → (상품이 정확히 6개이면) `오늘 특가` 새로고침 순서로 이동 버튼을 표시한다. `extra.source`는 새로고침을 `promotion_refresh`로 구분하며, 진입·노출·상품 클릭 이벤트를 기록한다. 새로 등록해야 하는 발화는 `오늘 특가`다. 기존 `/promotions/toss-shopping`의 `쇼핑 특가` 발화는 하위 호환용으로 유지한다.

카카오 관리자 등록 시 버튼 `label`과 `messageText`를 구분한다. 위 발화는 서버 설정의 `message_text`와 정확히 일치해야 하며, admin의 문구를 바꾸면 새 발화를 카카오에도 등록해야 한다.

### POST /cafeteria/menu/day

기숙사 식단은 한국 시간 기준 이번 주 월~일 날짜와 7개 요일·메뉴 항목을 검증한 뒤 응답한다. 누락·손상·오래된 식단은 `dorm-menu-monitor`가 **일요일 19:00~월요일 09:00(KST)에만 15분 간격으로** 공식 식단 1~2페이지에서 이번 주 데이터로 복구한다. 그 외 시간에는 자동 점검·수집을 하지 않는다. 복구 전에는 지난주 메뉴 대신 갱신 대기 안내와 기존 월~일 버튼을 반환한다. `/cafeteria/menu/today`의 기숙사 요청도 동일한 검증을 사용한다. 구현 완료 상태이며 기존 POST 경로·messageText를 유지하므로 새 카카오 등록은 필요 없다. 오늘 메뉴 경로의 운영 발화 등록 여부는 이 변경으로 새롭게 확인했다고 간주하지 않는다.

사용자가 요일+식당 조합으로 등록하는 방식임을 확인했다. 기숙사 조합은 다음과 같다. 실제 운영 요일의 데이터 유무와는 별개다.

요청한 요일에 메뉴 데이터가 없어 `운영 중인 메뉴가 없어요 🥲`를 반환할 때도 동일한 월~일 퀵리플라이를 표시한다. 각 버튼의 `messageText`와 POST 경로는 기존 요일별 매핑을 그대로 사용하므로 새로 등록할 발화는 없다.

## 학교혜택 매핑

기능별 POST 매핑을 기준으로 구현되어 있다. 사용자의 최종 발화 수정은 구현과 이 문서에 함께 반영한다.

| POST 경로 | 등록할 정확한 메시지 |
|---|---|
| /benefits/home | 학교혜택, 학교 혜택 |
| /benefits/list | 학교혜택 최신, 학교혜택 마감임박, 학교혜택 장학금, 학교혜택 교육, 학교혜택 해외교류, 학교혜택 인턴창업, 학교혜택 교내채용 |
| /benefits/page | 학교혜택 다음 |

학교혜택 접두어로 다른 기능의 발화와 충돌을 피한다. 버튼 label은 '장학금', '다음 5개' 등으로 짧게 표시하되 messageText는 위 등록 문자열과 일치한다.

## 학교혜택 UX 변경에 따른 정리

목록의 `자세히 보기` 버튼은 이제 `webLink`로 공식 공고를 바로 연다. 따라서 새 카카오 블록에는 아래 메시지를 등록하지 않는다.

- `학교혜택 1번` ~ `학교혜택 5번`: `/benefits/detail`로 가던 예전 상세 진입. 현재 목록 버튼에서 사용하지 않는다.
- `학교혜택 이전`: 이전 페이지 버튼을 제공하지 않으며, 현재 구현의 사용자 상태 기반 이전 탐색도 등록하지 않는다.
- `학교혜택 목록`: 번호 상세 화면에서 목록으로 돌아가던 예전 흐름. 직접 공식 공고로 이동하는 현재 흐름에는 필요하지 않다.

기존에 이미 등록했다면 위 메시지는 카카오 관리자에서 삭제하거나 비활성화한다. `/benefits/detail` 엔드포인트는 구버전 말풍선 호환을 위해 당분간 서버에 남겨두지만, 신규 등록 대상이 아니다.

## 상세·페이지 처리 제안

- 고정 발화만으로 사용 가능하도록 사용자별 최근 목록 상태를 DB에 보관한다: 분야, 정렬, 페이지 커서, 노출한 1~5번 공고 ID, 생성/만료 시각.
- /home은 최신 목록 5개를 표시하고 상태를 생성한다. /list는 선택 조건으로 목록 상태를 교체한다.
- /detail은 구버전 말풍선 호환용으로만 최근 목록의 번호를 해석한다. 신규 카드에서는 호출하지 않는다.
- /page는 `학교혜택 다음`에만 사용한다. 이전·목록 상태는 신규 UX에서 제공하지 않는다.
- 상태 만료는 마지막 목록 생성 후 30분으로 제안한다. 없거나 만료되면 최신 목록을 다시 제공하고 재선택을 안내한다. Redis나 메모리에만 저장하지 않아 프로세스 재시작·복수 워커에도 일관성을 유지한다.
- 고정 번호만 쓰면 과거 말풍선의 1번도 가장 최근 목록의 1번으로 해석된다. 화면에 '번호 선택은 가장 최근 목록 기준'을 안내한다. 과거 카드에서도 원래 공고를 보장하려면 검증된 clientExtra 전달 등 별도 설계가 필요하다. 이 한계를 숨기지 않는다.
- 임의 검색어를 붙이는 '학교혜택 검색 토익' 등은 정확한 고정 발화 매핑만으로 지원된다고 가정하지 않는다. 자유 검색은 패턴/엔티티 또는 fallback 연결 설계 후 별도 추가한다.

## 완료 시 인계

구현된 POST 경로와 테스트된 messageText를 위 표에 반영하고 미구현 표시를 제거한다. 응답의 모든 messageText가 등록표에 포함되는지 확인한다. API 테스트와 카카오 관리자 등록 후 실제 메시지 연결 확인을 구분하여 보고한다.

## 학교 주변 맛집

첫 화면의 `🎲 바로 추천`은 궁동·어은동·죽동에서 확인된 1인 기준 2만원 미만 메뉴를 가진 식당 한 곳을 보여준다. `🔄 다시 뽑기`는 같은 발화로 다른 식당을 고르며, `⚙️ 조건 고르기`는 기존 첫 화면으로 돌아간다. 조건 탐색은 지역 → 예산 → 최대 3곳 추천으로 연결한다. 학식 시간표·요일 메뉴(빈 메뉴 안내 포함)의 `🍽️ 학교 주변 맛집` label은 정확한 `messageText=학교 주변 맛집`을 전송한다. `RESTAURANTS_ENABLED=true`로 설정한 경우만 학식 진입 버튼을 표시한다. 기존 학식 / 셔틀 / 학교혜택 독립 메뉴 구성은 유지한다.

아래 POST 스킬과 발화 처리 구현 및 API 검증은 완료했다. 카카오 관리자 등록·실기기 연결 검증은 별도다. `restaurant-collector`가 카카오 Local API로 궁동·어은동·죽동 음식점을 찾고, 일반 공개 장소 페이지가 사용하는 메뉴·집계 평점 응답에서 등록 가격과 별점을 수집한다. 공식 Local API 자체가 별점을 제공하는 것은 아니다. 최초 수집 전·수집 실패로 유효한 메뉴가 없을 때는 준비 중 안내를 반환한다. 이번 랜덤 추천에서 새로 등록할 발화는 `주변맛집 랜덤` 하나이며 기존 발화의 messageText는 바뀌지 않았다.

랜덤 추천은 유효한 메뉴·가격과 카카오맵 별점 3.0 이상·평가 10개 이상을 확인한 활성 식당만 사용하며 2만원 미만 가격은 1인 비용 기준이다. 현재 탐색에서 보지 않은 식당을 먼저 고르고 최근 7일 미노출을 우선한다. 후보를 모두 보면 이전에 본 곳을 다시 고를 수 있으며, 그 사실을 안내한다. 빈 결과는 조건 탐색으로 안내한다. 사용자 상태 저장이 불가능하면 한 곳 추천은 제공하되 반복 방지를 보장할 수 없어 `다시 뽑기` 버튼을 숨긴다. 새로운 카카오 발화는 서버 구현·API 검증 후 등록 가능하며 카카오 관리자 등록 및 실기기 검증은 별도다.

예산 경계는 메뉴 비용 10,000원 미만 / 10,000~19,999원 / 20,000원 이상이다. 수동으로 인원을 확인한 세트는 총액과 인원을 표시하고 1인 비용의 원 미만은 올림한다. 자동 수집은 음료·주류·추가 항목·어린이 메뉴·100g당 단가·시가·공유/최소 주문 조건이 있는 메뉴를 제외하며 메뉴 가격과 인원수를 추정하지 않는다. 수집일은 현재 페이지를 읽은 날짜이며 실제 매장 가격을 새로 확인했다고 표시하지 않는다. 조회일과 원문 메뉴 등록일은 카탈로그에서 구분해 보관한다. 오래된 메뉴 가격에만 방문 전 확인 안내를 표시한다. 메뉴 가격은 미래 확인일과 조회/확인 후 30일 초과를 제외한다. 같은 장소는 한 카드만 표시하며, 여러 적격 메뉴 중 가장 저렴한 구성을 보여준다. 최근 7일 미노출을 우선하고 음식 종류를 분산한다. 한 번의 순환에서 이미 본 식당을 제외하고, 모두 본 뒤 다시 둘러보기로 순환한다.

별점은 허용된 카카오 데이터에 한정한다. 기본 추천은 확인 후 7일 이내 별점 3.0 이상·평가 10개 이상만 사용하고, 별점 선택은 이 기준보다 높은 3.5 / 4.0 / 4.5 조건을 추가한다. `ratings_enabled`와 이용 근거가 있고, 공개·유효 메뉴가 있는 식당에 확인 후 7일 이내 평점이 있을 때만 필터 진입 버튼이 나타난다. 미확인·오래된 평점은 제외한다. 조건 부족 시 자동으로 가격·별점을 완화하지 않는다. 기존 평점 조건이 적용된 상태에서 데이터가 만료·비활성화되면 조건을 유지한 빈 목록과 별점 전체 버튼을 제공한다.

PostgreSQL에 사용자 ID의 SHA-256 해시로 30분 탐색 상태와 7일 노출 이력을 보관한다. 홈 재진입·지역/예산 변경은 별점을 초기화하며, 별점 변경은 지역·예산을 유지한다. 별점 메뉴를 열 때는 노출 이력을 소비하지 않는다. 재추천·별점은 **현재 세션의 조건**에 적용되므로 오래된 말풍선을 눌러도 응답 상단의 현재 조건을 확인한다. 세션이 만료되면 지역부터 다시 고른다.

사용자 ID 누락·DB 실패 시 지역이 포함된 예산 발화로 기본 추천을 계속 제공하고 재추천·별점 버튼은 숨긴다. 이때 노출·클릭 계측을 했다고 표시하지 않는다.

`메뉴·후기 보기`는 기존 카카오맵 webLink이며 신규 발화 등록이 없다. HTTPS `SERVER_URL`과 추적 비밀값이 있으면 서명된 `/restaurants/map` 링크를 거쳐 이동하고, 없으면 카카오맵으로 직접 연결한다. GET 경로는 링크 이동·계측 전용이며 챗봇 데이터 조회 스킬로 등록하지 않는다. 원시 사용자 ID는 링크나 식당 이벤트에 담지 않는다. 클릭은 같은 링크의 중복 요청을 한 번만 기록하며, 실제 식당 방문을 의미하지 않는다.

식당 등록·카카오 장소 검색·미리보기는 인증된 `/admin/restaurants`에서 제공한다. 관리자 API는 카카오 스킬로 등록하지 않는다. 운영 방법은 [맛집 추천 운영 안내](restaurants.md)를 참조한다.

## 오늘 특가 대체 추천

오늘 특가가 비거나 표시 가능한 특가가 없으면 같은 POST `/promotions/collections/today-deals`와 발화 `오늘 특가`에서 할인율 높은 상품을 최대 6개 제공한다. 기존 경로와 발화는 구현 완료 상태이며 추가 카카오 등록은 필요 없다. 응답에 “오늘 특가 대신 할인율 높은 상품을 모았어요 🛍️”를 표시하고, 학식 인라인 카드에도 “할인율 높은 추천 상품”을 표시한다.

대체 후보는 저장된 식품·생활용품 상품 중 5만원 이하, 할인율 40% 이상을 우선하며 부족하면 30% 이상까지 확대한다. API 할인율은 가격으로 계산한 할인율을 넘지 않게 제한한다. 일반 상품의 48시간 유효기간, 품절·만료 제외, 학생 제외 기준을 적용하고 저장된 제휴 링크가 있는 상품만 사용한다. 같은 품목은 하나, 같은 그룹은 기본 2개·부족하면 3개까지 표시한다. 각 할인 구간에서 미노출 상품 우선, 소진 후 오래된 노출 순으로 순환하고 할인율을 우선 비교한다. 새로고침은 기존 `오늘 특가` 발화를 사용하며 요청 중 외부 상품 API를 호출하지 않는다. 대체 후보도 없으면 준비 중 안내를 표시한다. 노출·클릭에는 `selection_mode=high_discount_fallback`을 기록하고 어드민에도 대체 추천 상태를 표시한다.

## 학식 상품 정책 실험실

실험실 구현은 기존 POST 학식 응답의 상품 빈자리만 A(현행 1개)/B(학생용 최대 3개)로 바꾼다. 관리자 초안 저장으로 무작위 실험이 시작되지는 않는다. 시작 게이트를 통과한 뒤 인증된 어드민에서 명시적으로 모집을 시작해야 한다. A/A는 양쪽 모두 현행 1개를 제공한다.

신규 카카오 발화는 없다. 아래 경로와 정확한 발화는 구현되어 있으며 기존 등록을 그대로 사용할 수 있다. 운영 카카오 관리자 등록 및 실기기 렌더링 확인은 별도다.

| POST 경로 | 정확한 messageText | 실험에서 유지하는 흐름 |
|---|---|---|
| `/cafeteria/menu/day` | `월요일기숙사`, `화요일기숙사`, `수요일기숙사`, `목요일기숙사`, `금요일기숙사`, `토요일기숙사`, `일요일기숙사` | 기존 식단·아침 복원·요일 탐색, 빈자리 상품 슬롯만 변경 |
| `/promotions/collections/today-deals` | `오늘 특가` | 기존 최대 6개 목록 |
| `/promotions/collections/food` | `자취생 먹을거 핫딜` | 기존 최대 6개 목록 |
| `/promotions/collections/living` | `자취생 꿀템` | 기존 최대 6개 목록 |

전체 URL 예시: `https://example.com/cafeteria/menu/day`. 다른 식당·오늘 메뉴의 운영 발화 등록은 이 표에서 새롭게 확인했다고 간주하지 않는다. 학교혜택·셔틀의 독립 메뉴는 유지한다.

관리자 미리보기와 다음 조회 예약은 `/admin/api/experiments/{id}/preview`, `/preview-override`를 사용하는 인증된 어드민 기능이다. 카카오 스킬 URL이나 사용자 발화로 등록하지 않는다. 예약은 비공개 환경 설정의 개발자 계정에만 적용하고 다음 적격 조회에서 1회 소비하며 10분 후 만료한다. QA 반복 응답은 별도 surface로 기록하여 하루 운영 cap을 소모하지 않는다. QA 표식은 링크 서명에 포함하며 정식 ITT 클릭에서 제외한다. 과거 운영 노출 기록은 삭제하지 않는다.


## 식당 입력 검증

`POST /cafeteria/menu/today`와 `POST /cafeteria/menu/day`는 인식되지 않은 식당 입력으로 데이터 파일을 열지 않고 식당 이름 확인 안내를 반환한다. 구현 완료 후 기존 POST 등록과 정확한 발화를 그대로 사용하며 새 버튼·발화 등록은 없다. 정상 요일·식당 입력과 최상위 메뉴 구성은 유지한다.


## 개발자 전용 먹거리 처치 미리보기

관리자 예약의 `policy=student_food_preview_v2`는 저장 후보에서 표시 가격 5,000원 이하 간편식·간식을 최대 3개 고르고 생활용품을 제외한다. 상품 구성·가격 확인은 기존 서명 webLink이며 메시지 발화를 추가하지 않는다. 가격은 상품 표시 가격이며 확인되지 않은 배송 포함 총액을 보장하지 않는다. 유효한 서로 다른 후보가 부족하면 1~2개를 보여준다.

실기기 예약은 비공개 환경 설정의 개발자 계정에만 적용하며 다음 적격 학식 조회 1회, 10분 후 만료다. 빈 응답 슬롯이 없으면 소비하지 않는다. 공식 사용자 배정·클릭·활동일·하루 cap에서 제외한다. 일반 사용자 정책과 기존 상품 목록은 유지한다. 관리자 미리보기 구현 완료, 신규 카카오 등록 없음. POST 경로와 정확한 발화는 위 기존 `/cafeteria/menu/day` 등록표를 그대로 사용한다. 다른 식당의 발화가 자동 매핑된다고 가정하지 않는다.


### 새 가설의 개발자 전용 1만원 이하 먹거리 미리보기

`policy=student_food_preview_v3`는 저장된 상품 스냅샷에서 표시 가격 1만원 이하 먹거리만 골라 서로 다른 품목군 최대 3개를 저가 우선으로 보여준다. 상품 카드의 `⚡️ 자취생 특가 · 1만원 이하 먹거리`는 설명 label이며, `구성·가격 확인`은 기존 서명 webLink다. 상품 가격에 배송비가 포함됐다고 표시하지 않는다. 후보가 적으면 실제 1~2개를 보여주고 후보가 없으면 미리보기 API가 사유를 반환한다.

관리자 화면에서 실기기 예약을 누르면 비공개 환경 설정의 개발자 계정에만 다음 적격 학식 조회 **1회** 적용되며 24시간 후 만료한다. QA 클릭과 노출은 정식 A/B 표본·클릭 및 일일 노출 cap에 포함하지 않는다. 공식 사용자 처치 정책과 기존 최대 6개 상품 목록은 변경하지 않는다. 구현 완료, 신규 카카오 발화 등록 없음. 정확한 기존 등록은 `POST https://example.com/cafeteria/menu/day`의 `월요일기숙사`, `화요일기숙사`, `수요일기숙사`, `목요일기숙사`, `금요일기숙사`, `토요일기숙사`, `일요일기숙사`; 다른 식당 발화는 위 표에서 별도 등록 확인이 필요하다. 먹거리 목록 버튼 `messageText=자취생 먹을거 핫딜`은 기존 `POST https://example.com/promotions/collections/food`에 연결된다.

## 정식 먹거리 A/B의 기존 카카오 연결

[24시간 먹거리 탐색 A/B 운영 계획](cnubot-fast-food-experiment.md)의 B 정책은 학식 기존 POST 응답 슬롯에서만 적용한다. 신규 발화는 없으며, 이 문서의 `/cafeteria/menu/day`와 `/promotions/collections/food` 정확한 messageText 등록표를 그대로 사용한다. 신규 정책은 서버 구현 완료 후 실험 상태가 `running`일 때만 일반 사용자에게 무작위 배정된다. 개발자 QA 미리보기는 정식 표본에서 제외한다.

## 시간표 단일 먹거리 버튼

시간표의 상품 진입 퀵리플라이는 먹거리 하나로 정리했다. 기존 식단 보기·혼잡도 버튼과 상품 기획전의 최대 6개 목록은 유지한다. 제거한 퀵리플라이의 API나 발화 등록을 삭제할 필요는 없다.

| POST 경로 | 버튼 label | 정확한 messageText | 상태 |
|---|---|---|---|
| `/promotions/collections/food` | `⚡️ 자취생 특가` | `자취생 먹을거 핫딜` | 구현 완료, 기존 등록 사용 가능, 신규 등록 없음 |

URL 예시: `https://example.com/promotions/collections/food`. 클릭 출처는 실제 전달된 `extra`/`clientExtra`만 사용한다. 출처가 없는 입력을 시간표 퀵리플라이 클릭으로 추정하지 않는다.

시간표 버튼의 표시명은 사용자 요청으로 `⚡️ 자취생 특가`이며 클릭 계측의 `button_label`도 같은 값이다. `messageText`는 기존 `자취생 먹을거 핫딜`을 유지하므로 카카오 발화 재등록은 필요 없다.
