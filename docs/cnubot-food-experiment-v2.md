# 학식 맥락의 저가 먹거리 추천 실험 v2

- 후속 실행안: [24시간 먹거리 탐색 A/B 운영 계획](cnubot-fast-food-experiment.md). 이번 실험의 관찰·모집·판정은 후속안을 우선한다.
- 설계일: 2026-10-13 KST
- 상태: 재설계 완료 / 정식 처치 구현·시작 전 검증 필요 / 이 문서 작성으로 실험이 시작되지는 않음.
- 이번 A/B의 후속 설계다. 기존 [어드민 설계](cnubot-experiment-admin-design.md)의 일반 계측·보안·분석 계약은 유지하고, 처치·표본·모집 계획·판정 목적은 이 문서를 우선한다. 기존 A/A 기록과 프로토콜을 소급 변경하지 않는다.

## 1. 결정할 문제와 가설

**학식 이용자에게 카테고리를 순환하는 단일 상품 대신, 서로 다른 저가 먹거리 3개를 한 캐러셀로 제공하면 학식 이용을 해치지 않으면서 7일 내 외부 상품 클릭 사용자 비율이 증가하는가?**

사업적 결정은 기존 추천 정책을 먹거리 중심 정책으로 교체할 가치가 있는지다. 상황 적합성과 선택 폭을 함께 바꾸는 패키지 실험이다. 결과는 패키지 전체의 인과 효과이며, 가격·카테고리·개수·문구 각각의 기여로 분해하지 않는다.

가능한 작동 원리는 학식을 확인하는 이용자에게 먹거리의 관련성이 높고, 한 상품에 관심이 없어도 다른 품목을 고를 수 있다는 것이다. 이는 검증할 가설이지 확인된 사용자 심리가 아니다. 3개가 최적 개수라는 근거도 아직 없다.

## 2. 근거와 선택

기존 분석의 관측 종료는 2026-10-13 00:00 KST. QA·개발자·식별자 없는 이벤트를 제외했다. 아래 경로별 비율은 서로 다른 모집단의 관측치이며 무작위 비교 결과가 아니다.

| 관측 | 수치 | 설계 해석 |
|---|---:|---|
| 14일 시간표 퀵리플라이, 노출 사용자 대비 클릭 사용자 | 먹거리 24/1,678, 오늘 특가 17/1,678, 생활 6/1,678 | 먹거리 우선순위를 정할 약한 방향성 |
| 인라인 상품 외부 클릭 사용자 | 먹거리 5/1,791, 생활 3/1,773, 오늘 특가 2/1,801 | 클릭이 매우 적어 카테고리 우위를 확정할 수 없음 |
| 먹거리 목록 외부 클릭 사용자 | 9/111 | 이미 진입한 사용자는 의도가 다르므로 인라인 대비 상승률로 사용 금지 |
| 먹거리 목록의 클릭된 카드 노출 | 10건 중 위치 4~6에서 6건 | 기존 직접 진입 6개 목록을 보존할 이유. 인라인 6개가 우월하다는 증거는 아님 |
| 현행 정책의 168시간 성숙 코호트 | 7/1,371 = 0.5106% | 표본 설계의 잠정 기준율 |

현재 스냅샷을 읽기 전용으로 확인한 결과, 기존 품질·학생 적합성·서로 다른 품목군 조건에서 5천 원 이하 먹거리는 2개(4,440원·3,700원), 1만 원 이하는 3개(추가 5,300원)가 선정됐다. 이는 한 시점의 선정 결과이며 일주일 공급 보장이 아니다.

**5천 원 제한을 풀고, 1만 원 이하에서 저가 우선으로 3개를 선정한다.** 5,300원 상품을 배제할 사업적 근거가 없고, 후보 2개뿐인 정책은 품절 시 선택 폭이 쉽게 줄어든다. 가격 상한을 넓혔다고 효과가 커진다고 단정하지 않는다.

대안 비교:

| 대안 | 이번 결정 |
|---|---|
| 버튼 문구만 변경 | 이미 양 군 공통 UX로 변경됨. 희소 클릭 환경에서 첫 실험의 핵심 처치로 삼지 않음 |
| 같은 먹거리 풀에서 1개 대 2개 | 개수의 효과는 해석하기 쉽지만 기존 정책 교체라는 현재 질문과 다름 |
| 5천 원 이하 먹거리 2개 | 가격 경계가 임의적이고 현재 후보 여유가 부족함 |
| 저가 먹거리 3개 | 관련성과 선택 폭을 함께 개선하는 이번 처치로 선정 |
| 자동 노출 횟수 증가 또는 6개 확대 | 추가 광고 부담까지 동시에 늘리므로 후속 실험으로 유보 |

## 3. A/B 경험과 고정 정책

| 항목 | A | B |
|---|---|---|
| 추천 | 기존 today_deals / food / living 순환 1개 | 먹거리만, 서로 다른 품목군 최대 3개 |
| 가격 | 현행 정책 | 표시 가격 1만 원 이하, 저가 우선 |
| 출력 | 기존 상품 슬롯 1개 | 같은 슬롯의 가로 commerceCard 캐러셀 |
| 안내 | 현행 | `⚡️ 자취생 특가 · 1만원 이하 먹거리 · 제휴` |
| 외부 이동 버튼 | 현행 | `구성·가격 확인` |
| 빈도 | 사용자별 KST 하루 최대 1회 | 동일 |
| 직접 진입 목록 | 기존 최대 6개 | 동일 |
| 시간표 퀵리플라이 | `⚡️ 자취생 특가` 1개 | 동일 |

B 정책 식별자 제안: `student_food_bundle_v2`. 개발자용 `student_food_preview_v2`와 구분한다.

선정 순서는 시작 전에 코드·설정 해시로 고정한다.

1. 저장된 상품 스냅샷에서 유효 링크·가격·재고·기존 할인 및 품질 기준을 통과한 먹거리만 사용한다. 기존 학생 제외·대용량 제외 규칙을 유지한다.
2. 기존 meal/snack 분류별로 1개씩 우선하고, 남은 자리는 다른 품목군으로 채워 최대 3개를 만든다. 분류상 meal에 반찬도 포함되므로 ‘한 끼 완성’, ‘식사 대체’라고 광고하지 않는다.
3. 각 선택 단계의 순위는 미노출 우선 → 마지막 노출이 오래된 순 → 표시 가격 오름차순 → 리뷰 점수 내림차순 → 할인율 내림차순 → 상품 ID 순이다. 기존 선택기와 동일한 결정 규칙을 재사용한다.
4. 2개면 2개, 1개면 1개, 0개면 공통 적격 판정 때 확보한 A 상품을 제공한다. 실제 개수와 대체 사유를 기록하고 모두 B 분석에 남긴다.
5. 실험 중 정상 가격·재고 갱신은 허용한다. 가격 상한·분류·순위·문구·개수·빈도는 수정하지 않는다. 변경이 필요하면 종료 후 새 실험으로 만든다.

상품 가격은 배송 포함 결제 총액이 아니다. 배송·수량 정보가 확인되지 않으면 무료배송, 1인분 가격, 품절 임박, 최저가 등을 만들어 쓰지 않는다. 개별 상품의 실제 이름·구성과 표시 가격을 사용한다.

## 4. 대상·배정·계측

- 새 실험 키로 사용자 단위 50:50 고정 배정. A/A 배정·미리보기를 새 표본에 합산하지 않는다.
- 공통 적격: 식별 가능한 비QA 사용자, 해당 날짜의 자동 노출 기회 미사용, 기존 상품 슬롯 존재, 유효 A 후보 존재. B 후보 수와 무관하게 먼저 판정한다.
- 최초 배정 시각 t0부터 168시간 관찰. 요청 실패·B 후보 부족·이후 미방문도 배정군에 유지하는 ITT 분석이다.
- 신규·기존 이용자를 모두 포함한다. 가입/사전 활동 여부·최초 식당별 분석은 탐색에 한정한다.
- 이벤트에 실험/설정 버전, 배정군, 실제 정책, 요청/묶음 ID, 위치, 카드 수, 가격, 스냅샷, 대체 사유를 남긴다. QA는 별도 표식으로 제외한다.
- 응답에 카드가 포함된 사실을 계측하며 실제 시선·스와이프를 측정했다고 표현하지 않는다. 사용자당 중복 클릭은 주 지표에서 1건이다.

## 5. 지표와 판정

**주 지표: 배정 후 168시간 내 모든 상품 경로에서 유효한 외부 상품 클릭을 1회 이상 기록한 사용자 / 전체 배정 사용자.** 인라인에서 직접 목록으로 경로가 이동하는 효과까지 포함한다. 구매·매출 상승으로 해석하지 않는다.

- 양측 Fisher exact α=0.05, 비율 차이의 Newcombe-Wilson 95% CI.
- 큰 개선 신호: p<0.05, 관측 차이 ≥+1.0%p, CI 하한 >+0.5%p. 이 한계는 기존 계획의 사업적 제안값을 유지한 것이며 수익 최적화로 입증된 값은 아니다.
- 학식 안전성: 사전 14일 활동일로 보정한 168시간 학식 활동일 차이의 95% CI 하한 >-0.20일. θ는 시작 전 성숙 자료에서 고정한다. 유의한 악화가 없다는 이유만으로 안전 판정하지 않는다.
- 보조: 인라인 외부 클릭 사용자, 직접 목록 진입 사용자, 전체 클릭 수, B 3개 제공률·대체율, 요청 오류·p95. 보조 지표만 좋아져도 성공으로 바꾸지 않는다.
- A/A를 조기 중단했으므로 이번은 탐색적 실험으로 기록하고 중단 이유·진단 미완료를 명시한다. 자동 채택하지 않는다.

| 최종 관측 | 결론과 다음 행동 |
|---|---|
| 품질·표본·큰 개선·안전성 모두 충족 | 유망한 정책 신호. 한계와 함께 후속 검증/확대 검토 |
| 작은 양의 효과 또는 넓은 CI | 불확실. 효과 없음이나 성공으로 단정하지 않음 |
| 목록 진입만 증가, 외부 클릭 개선 불명확 | 상품 적합성·가격/구성 정보의 다음 가설을 탐색 |
| 안전성 실패·유해 방향 | 확대 보류, 학식 경험 영향 조사 |
| 품질 실패 또는 표본 미달 | 계획 미충족으로 보고. 사후 표본 목표 축소 금지 |

## 6. 표본·기간

- 목표: 총 2,000명, 예상 군별 약 1,000명.
- 새 권장 모집 규칙: 2,000명 도달 또는 시작 후 14×24시간 중 먼저 도래할 때 종료. 이전 7일 모집 요청에 대한 이번 재설계 제안이며 운영 설정을 변경한 상태는 아니다.
- 목표 미달 시 자동 연장하거나 목표를 줄이지 않는다. 확보 표본·불확실성을 보고한다.
- 마지막 배정자까지 168시간 관찰하고 24시간 수집 유예 후 최종 분석. 모집이 일찍 끝나도 동일하다.
- 과거 고유 적격 누적에서 7일 1,902명, 다른 12일 창 2,038명이 관측돼 모집 약 10~14일을 계획 범위로 사용한다. 서로 다른 기간의 관측으로 새 코호트의 2,000명 도달을 보장하지 않는다. DAU 합산을 표본으로 쓰지 않는다.
- 따라서 시작부터 최종 분석까지 계획상 약 18~22일. 다음 주 포트폴리오에는 설계·구현·품질 검증과 중간 모집 현황을 쓰며 최종 uplift를 미리 쓰지 않는다.

기준율 7/1,371, 총 2,000명, 독립 50:50 무작위 배정, 저장소 시뮬레이터의 100,000회 기존 계산:

| 실제 효과를 가정한 시나리오 | 양의 유의성 통과 | 큰 개선 신호 기준까지 통과 |
|---|---:|---:|
| +1.0%p | 약 58.0% | 약 18.5% |
| +2.5%p | 약 99.4% | 약 95.1% |

조건부 확률이며 처치 성공 가능성이나 안전성까지 포함한 확률이 아니다. +2.5%p는 기준 0.51%에서 3.01%로 약 5.9배 상승하는 큰 가정이다. 기대 효과로 약속하지 않는다. 현행 시간표 UX 변경 후 기준율의 이동 가능성을 명시하고 시작 전 최신 성숙 코호트·seed·계산 버전을 새 초안에 저장한다.

유의성을 보고 조기 종료하거나 기간을 늘리지 않는다. 운영 장애 대응 중단은 허용하되 이유와 영향을 기록한다. 표본·효과·기간의 관계는 [Statsig Power Analysis](https://docs.statsig.com/experiments/power-analysis)의 계획 원칙을 참고했다.

## 7. 시작 전 구현·검증 계약

1. 공식 B 선택기를 새 먹거리 정책으로 연결한다. 현재 공식 B는 생활용품을 포함하는 기존 3개 정책이다. 미리보기 변경만으로 완료 처리하지 않는다.
2. 새 정책의 QA 미리보기, 실제 버튼 label과 서명된 클릭 메타데이터의 일치, 3/2/1/0개 후보·실패·재시도·날짜 경계·관찰 종료 테스트를 수행한다.
3. 신규 정책을 개발자 실기기에서 확인한다. 기존 3개 미리보기 확인을 변경된 정책의 확인으로 대체하지 않는다.
4. 최소 하루 동안 수집된 각 상품 갱신 스냅샷에서 3개 확보 여부를 점검하고 결과·분모를 저장한다. 3개 확보율 목표 90%. 현재 한 번의 3개 선정만으로 통과 처리하지 않는다. 사용자별 과거 노출은 순위를 바꾸며 동일 스냅샷 반복 조회를 독립 재고 검증으로 세지 않는다.
5. 이벤트 연결, QA 제외, 중복 배정, SRM, 실패 응답 보존을 검증한다. 기존 잘못된 식당 입력의 오류 수정도 배포 회귀 검증에 포함한다.
6. p95 한계는 실제 카카오 응답 제한과 운영 측정에 근거해 시작 전 설정한다. 기존 계획의 치명 오류 및 군별 오류율 경보를 적용하고 카드 부족을 사용자 제외로 해결하지 않는다.

새 카카오 발화나 POST 경로는 추가하지 않는다. 기존 `먹거리 더 보기`의 messageText는 `자취생 먹을거 핫딜`, POST는 `/promotions/collections/food`다. 시간표의 `⚡️ 자취생 특가`도 같은 발화를 유지한다. 외부 `구성·가격 확인`은 추적 webLink이며 발화 등록 대상이 아니다. 기존 목록 API는 구현·등록 가능 상태, 새로운 공식 B 정책은 구현 전이다. 상세 등록표는 [카카오 메시지 규약](kakao-message-routing.md)을 따른다.
