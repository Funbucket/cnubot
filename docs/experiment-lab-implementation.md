# 상품 정책 실험실 구현 및 운영 인계

2026-10-08 KST. 기준: [설계](cnubot-experiment-admin-design.md).

## 구현 범위

- `/admin/experiments`: 공통 실험 목록, 6단계 계획 입력, 개요·결정, 결과, 데이터 품질, A/B 경험 미리보기, 설계·감사 이력. 현재 버튼 A/B도 같은 목록·상세 UI에 통합한다. 이전 기록은 `/admin/experiments/legacy`에 보존한다.
- 사용자 50:50 해시 배정과 영구 저장, QA/식별자 없는 요청 제외. 공통 A 후보·슬롯 확인 뒤 B 후보를 조회한다. 배정은 응답 포함 기록 전에 저장하여 응답 실패와 후보 부족을 ITT에 남긴다.
- 하나의 실험만 학식 상품 슬롯을 사용할 수 있다. 신규 모집 일시중지/마감 뒤에도 기존 배정자는 168시간 동안 원래 경험을 받는다. A/B는 전체 2,200명 또는 28일 상한으로 모집을 닫는다. A/A는 표본 목표에 먼저 닿아도 7일 동안 신규 모집하여 요일 범위를 검증한다. 마지막 배정 뒤 168시간과 24시간 수집 여유를 모두 기다린다.
- B 후보 1~2개도 B 유지, 후보가 전혀 없으면 공통 A 후보로 대체한다. 계획 군·렌더링 정책·실제 카드 수·대체 이유를 구분한다. 묶음 1기회와 상품 1~3건은 하루 cap과 같은 트랜잭션에 저장한다.
- 학식 라우터의 요청 처리기를 통해 이미 배정된 사용자의 cap 이후 요청·실패·지연도 기록한다. 중간 조회 실패와 기록 실패는 정상 0건으로 숨기지 않는다. 고정 운영 경보(5분 오류 3회, 또는 최근 15분 군별 100요청 이상·B 실패 5회·오류율 +1%p)는 긴급 중단으로 기록한다.
- 주 지표는 전체 경로의 외부 상품 클릭 사용자, 배정 시각부터 168시간의 반개구간이다. 상품키 또는 실험 링크 출처가 없어도 사용자·시간으로 귀속한다. 관찰 중 사용자를 클릭 0으로 넣지 않는다.
- 양측 Fisher exact, Newcombe-Wilson 95% CI, 고정 θ CUPED 활동일의 Welch t CI. 빈 군·0클릭·분산 미추정은 정직하게 표시한다. 클릭에는 CUPED를 적용하지 않는다.
- 분석 실행은 명시적인 POST이며 GET은 마지막 불변 스냅샷만 읽는다. 같은 idempotency_key는 같은 분석을 반환한다. watermark는 운영자가 확인한 수집 완전성 근거와 함께 입력한다. DB의 최신 이벤트 시각을 자동 완전성 보증으로 사용하지 않는다.
- 결과 유의성과 판단 준비를 분리한다. 표본 미달은 미결, 품질 실패는 품질 미결로 보고하며 미결/후속 계획만 기록할 수 있다. 효과·표본·안전성·품질이 모두 통과해야 채택 결정을 기록할 수 있다. 결정 기록은 B 정책의 자동 배포가 아니다.
- 다음 조회 QA 예약은 개발자 계정 고정·10분·적격 조회 1회다. QA 링크에 서명된 표식을 넣고 분석에서 제외한다. 브라우저 미리보기 자체로 노출·클릭 이벤트를 만들지 않는다.

## 저장 구조 및 API

`backend/app/migrations/001_experiment_lab.sql`을 시작 시 멱등적으로 적용한다. 기존 `experiments`, 배정, `user_events`는 보존하며 `lab_*` 테이블에 계획·배정·요청·묶음·분석·감사를 저장한다. 실제 사용자 식별자는 DB와 비공개 환경 설정에서만 관리한다. 새 라이브 실험은 새 키와 salt를 사용한다.

모든 경로는 기존 관리자 HTTP Basic 인증 안에서 제공한다. 변경 요청에는 실험실 화면이 보내는 `X-Experiment-Admin: 1` 헤더가 필요하다.

| 경로 | 동작 |
|---|---|
| `GET /admin/api/experiments` | 계획 목록과 마지막 결과 읽기 |
| `POST /admin/api/experiments` | 초안 생성 |
| `PUT /admin/api/experiments/{id}` | 시작 전 초안 수정 |
| `GET /admin/api/experiments/{id}/results` | 계획·마지막 스냅샷·감사·시작 차단 이유 |
| `GET /admin/api/experiments/{id}/diagnostics` | 마지막 진단 및 누락된 준비 항목 |
| `POST /admin/api/experiments/{id}/enrollment` | start/pause/resume/close, 이유 필수 |
| `POST /admin/api/experiments/{id}/stop` | 긴급 중단, 이유 필수 |
| `POST /admin/api/experiments/{id}/analysis-runs` | watermark·완전성 확인·이유·멱등 키로 분석 저장 |
| `POST /admin/api/experiments/{id}/simulation` | 고정 seed·반복 수·무작위 군별 인원으로 IID 검정력 재산출 |
| `POST /admin/api/experiments/{id}/preview` | 저장 상품으로 A/B QA 응답 생성 |
| `POST /admin/api/experiments/{id}/preview-override` | 개발자 다음 적격 조회 1회 예약 |
| `DELETE /admin/api/experiments/{id}/preview-override` | 개발자 예약 취소 |
| `POST /admin/api/experiments/{id}/decision` | 최신 run_id에 운영자 결정 저장 |

분석·시뮬레이션 POST는 첫 구현에서 요청 안에서 실행한다. 대규모 비동기 작업 큐와 진행 상태 API는 후속 구현 대상이다. `experiment-monitor` 서비스가 운영 실험의 스냅샷을 15분마다 갱신한다. 자동 집계는 수집 완전성을 확인했다고 주장하지 않으며, 최종 판정 전 운영자가 복구·누락 여부를 확인해 별도 분석을 실행한다.

## 시작 전 운영자가 확정할 입력

1. A/A: 계측·클릭 필터 검증 기록, 실기기 QA 결과, p95 한계, B 3개 확보율 기준을 입력한다. A/A는 양 군 A를 제공하므로 분석에서 3개 확보율을 통과 조건으로 쓰지 않는다.
2. A/B: 최신 성숙 기준율·기준일·근거(분산·θ·고유 신규 모집 가능성 포함), 최소 효과·안전성 허용 손실을 검토한다. 역사적 숫자를 최신 운영 관측으로 자동 채우지 않는다.
3. 현 계획 hash의 시뮬레이션을 실행하고 별도의 7일 A/A를 관찰 종료·수집 여유까지 완료한다. 최신 A/A 분석의 품질 통과가 시작 조건이다. 실제 준비 확인은 작성된 근거와 A/A 진단을 함께 검토한다.
4. 정책 소스 checksum과 protocol hash는 시작 후 고정한다. 선택·렌더링 코드 변경이 감지되면 B 제공 및 품질 통과를 막는다. 정상 가격·재고 갱신은 허용한다.

`DEVELOPER_ID`와 추가 `EXPERIMENT_QA_IDS`는 비공개 환경에서 설정한다. 기존 상품 추적 secret 및 저장된 제휴 링크가 필요하다. [카카오 등록표](kakao-message-routing.md)의 기존 발화를 그대로 사용하며 추가 등록은 없다.

## 클릭 필터와 수집 한계

`signed-external-v1`: 유효 서명·만료를 검증하고 알려진 bot/crawler/spider/preview 계열 User-Agent를 제외한다. 유효 링크 요청의 raw 이벤트를 별도로 남기고 반복 유효 클릭도 시각별로 보존하고 주 지표는 사용자당 최대 1명으로 계산한다. 배정 전 눌렀던 링크를 관찰 창 안에서 다시 누른 경우를 전역 토큰 중복 제거로 없애지 않는다. QA 표식은 서명된 토큰 메타데이터에서 읽는다. 필터는 사람이 실제로 눌렀는지를 완벽히 증명하지 않으므로 A/A에서 카카오 링크 미리보기 User-Agent를 확인해야 한다.

현재 이벤트는 서버 수신 시각 `created_at`을 event_time으로 사용한다. 외부 이벤트 지연 유입/클라이언트 시각·별도 received_at 계약은 아직 없다. 따라서 수집 장애 복구 없이 완전성을 확인하면 안 된다. 원시 클릭·필터 후 클릭과 서버 응답 포함은 사람의 실제 카드 조회·구매를 증명하지 않는다.

현재 품질 게이트는 기록된 요청 오류가 있으면 보수적으로 통과를 막는다. 운영 오류 원인의 복구·정상 요청 분류 및 경보 기준은 A/A에서 검토한다. 공식 활동일 분석은 `menu_view` 이벤트 기준이다. 식당별 하위그룹 탐색, 별도 지표 drilldown, 정기 분석 작업 큐, 데이터 완전성 모니터 연동은 P1 이후 범위다.

## 검증 및 남은 운영 작업

격리 PostgreSQL에서 동시 배정·원자적 하루 cap·묶음 기회·모집 일시중지/종료 후 경험·관찰 창 경계·QA 제외·멱등 분석·계획 잠금을 검증했다. Newcombe를 statsmodels와, Welch CI를 SciPy 독립 API와 비교했다. 브라우저에서 데스크톱·모바일 overflow, 시작/채택 게이트와 %p 단위 변환을 확인했다. 전체 회귀 테스트 169개와 하위 검증 45개가 통과했다. 추가 내용의 비공개 운영 설정 값·운영 절대 경로·IP 노출 검사도 통과했다.

2026-10-08에 backend와 상품 수집기 이미지를 재빌드하고 운영 컨테이너를 재시작했다. 재시작 전 비공개 DB 백업을 생성했으며, 새 실험 테이블 7개 적용, 어드민·실험 목록 API·이전 실험 화면·학식 시간표의 HTTP 200 응답을 확인했다. PostgreSQL은 healthy 상태이며 진행 중인 새 프로토콜 실험은 0개다.

카카오 실기기 QA, 최신 기준율·분산·모집 유입 재검증, 7일 Live A/A는 별도로 수행해야 한다. 이번 운영 배포는 실험 시작이나 채택 기준 승인을 뜻하지 않는다.


## 실험 시작 및 공통 어드민 UX

실험실과 인사이트는 공통 `admin_nav.css`의 페이지 스타일과 동일한 전체 폭 상단 메뉴를 사용한다. 배경·본문 폭·서체·색상·표·카드·버튼·모바일 여백을 공유한다. 실험 탭에는 키보드 좌우/Home/End 이동과 ARIA 연결을 제공하며, 상세 링크는 새로고침 후에도 복원한다. 실시간 배정 수와 마지막 스냅샷의 관찰 완료 분모를 구분한다. 표본 부족·수집 확인 대기는 품질 실패 대신 판단 대기로 표시한다.

사용자가 2026-10-08에 카카오 실기기의 가로 넘김·상품 이동·기존 6개 목록·기숙사 아침 복원이 모두 정상임을 확인했다. 시작할 단계는 별도 키의 7일 A/A이며 양 군 모두 현행 상품 1개를 받는다. 서버 p95 초기 한계는 2,000ms, 이후 B 묶음 완성률 초기 기준은 80%로 정하고 A/A에서 실제 운영 지연·수집 상태를 검토한다. A/A의 2,200명은 계획 참고 규모이며, 종료 기준은 7일 신규 모집과 마지막 배정자의 168시간 관찰·24시간 수집 여유다.

A/B는 완료된 A/A 진단·수집 완전성·최신 기준율/분산/θ/모집 가능성 재산출과 계획 검토 후 별도로 시작한다. 자동 집계 서비스가 A/A 종료를 대신해 A/B를 자동 시작하지 않는다. 신규 카카오 발화 등록은 없다.


2026-10-08 14:15 KST에 실험 #1 `학식 상품 추천 계측 검증 A/A`를 시작했다. 신규 모집 종료는 10월 15일 14:15, 마지막 배정자의 관찰 종료 상한은 10월 22일 14:15, 수집 여유를 포함한 최종 검토 가능 시점은 10월 23일 14:15 이후다. 시작 전 저장 후보 3개·서명된 QA 클릭 제외·운영 API를 확인했으며, 학식 시간표 8회 서버 smoke의 p95는 약 17.5ms였다. 이 값은 소규모 서버 점검값이며 실제 카카오 전체 지연의 기준율을 뜻하지 않는다. 전체 회귀 테스트 170개와 하위 검증 45개가 통과했다.


## 실험 상세 화면 UX

상세 화면은 실험 이름·현재 단계·다음 행동을 먼저 보여주고, 진행 현황 / 분석 결과 / 데이터 품질 / 경험 미리보기 / 설계·이력으로 나눈다. A/A는 2,200명 목표 대신 7일 모집 일정과 A/B별 실제 배정 수를 표시한다. 모집 마감·관찰·수집 확인 일정은 KST로 제공하며 예정 일정과 확인된 상태를 구분한다. 운영 기능은 접을 수 있는 별도 영역에 두고 현재 단계에서 가능한 작업만 보여준다. A/A에서는 B 확대 적용 버튼을 표시하지 않는다.

새로고침은 선택한 탭·운영 근거·수집 기준 시각·완전성 체크를 보존한다. 실행 중에는 중복 운영 요청을 막는다. 품질 진단은 군별 요청·오류·미완료·p95 표로, 설계와 운영 이력은 읽을 수 있는 설명으로 제공하고 원본 JSON은 접어 둔다. 데스크톱·모바일 레이아웃, 상세 링크, 키보드 탭 이동, 입력 보존, 조회 실패, 초안 시작 게이트와 A/A·A/B 최종 버튼을 브라우저에서 확인했다. 기존 실험 프로토콜 및 정책 코드는 변경하지 않았다.


## 미완료 A/A 이후 탐색 실험

2026-10-13 사용자 요청으로 A/A #1을 중단하고 기존 배정·분석·오류 기록을 보존했다. A/A 완료·품질 통과로 간주하지 않는다. 후속 A/B는 별도 키와 새 배정으로 생성하며 A/A 배정자를 A/B 표본에 합치지 않는다.

`purpose=exploratory`는 A/A 완료 요건의 명시적 예외이며 그 근거를 계획에 고정한다. 모집 기간(1~28일, 시작 시점 기준) 또는 timezone을 포함한 절대 마감 시각 중 하나를 사전에 정한다. 최신 기준율·실기기 QA·계측 근거·현재 계획 해시의 검정력 계산은 계속 요구한다. 모집 마감 뒤 기존 배정자의 168시간 경험·관찰은 유지하며 수집 여유는 24시간이다. 표본 미달이나 중간 값을 최종 성과로 해석하지 않는다. 탐색 실험은 확대 적용 결정 기록을 허용하지 않는다. 정식 검증 실험은 기존 7일 A/A 통과 게이트와 최대 28일 모집 규칙을 유지한다.

잘못된 식당 입력은 파일을 열기 전에 검증하여 카카오 안내 응답을 반환한다. 정상 식단 경로와 등록된 발화는 유지하며 신규 카카오 등록은 없다. 과거 요청 오류 기록은 삭제하거나 정상으로 변경하지 않는다.


## 먹거리 처치 검토용 QA

새 제안은 정식 실험 시작 전 개발자 전용 경험으로 확인한다. 관리자 미리보기·예약 API에서 `policy=student_food_preview_v2`를 지정하면 5천원 이하 간편식·간식 최대 3개와 구성·가격 확인 링크를 제공한다. 생활용품은 제외하며 배송비를 확인하지 못한 가격은 상품 표시 가격으로 표현한다. 실제 후보가 2개면 2개를 제공하고 3개를 확보했다고 표시하지 않는다. 예약 정책은 기존 QA 예약 테이블에 추가 컬럼으로 저장하며 과거 기록을 보존한다. 일반 사용자에게는 기존 정책을 제공하고 공식 B 정책은 변경하지 않는다. 새 정책으로 정식 실험을 시작하려면 별도 계획·정책 고정 및 QA 결과를 검토한다.


## 시간표 진입 버튼 정리

2026-10-13에 시간표의 상품 진입 퀵리플라이를 3개에서 먹거리 하나로 줄였다. 9월 29일~10월 12일 KST의 개발자·QA 제외, 출처가 확인되고 같은 기간의 선행 버튼 노출이 있는 사용자 기준으로 먹거리 24/1,678(1.43%), 오늘 특가 17/1,678(1.01%), 꿀템 6/1,678(0.36%)였다. 최근 7일도 먹거리 11/1,341, 오늘 특가 10/1,341, 꿀템 4/1,341이었다. 이 수치는 관측 진입 CTR이며 상품 구매·최종 외부 클릭 전환율이 아니다. 클릭 수가 적고 노출 위치 차이가 있어 우열의 인과적 확정이나 피로 감소 성과로 주장하지 않는다.

사용자가 원하는 버튼 수 감소를 위해 관측상 가장 높은 먹거리를 남겼다. 다른 기획전의 API·등록 발화·목록과 식단·셔틀·학교혜택 구성은 유지한다. 정식 A/B 시작 전의 공통 UX 변경이며 향후 양 군에 동일하게 적용한다. 변경 전후의 CTR을 같은 노출 조건의 실험 효과로 해석하지 않는다.

## 2026-10-14 정책 검증 오류와 복구

01:12 KST의 버튼 변경 배포가 `promotions.py` 전체 파일의 고정 정책 검증값을 바꿨다. 먹거리 실험에서는 `preparation_failed` 4건이 발생했고 01:20 KST에 고정 운영 경보가 자동 중단했다. 버튼 실험과의 무작위 배정 충돌이 아니라 코드 검증 범위에 문구 변경이 섞인 배포 오류였다.

버튼 생성 코드를 `menu_button_experiment.py`로 분리하고 상품 정책 파일을 고정된 원래 코드로 복원하여 저장 정책 검증값과 정확히 일치시켰다. 10:22 KST에 중단된 탐색 실험을 복구했다. 원래 계획·검증값·시작 시각·salt와 당시 817명 배정·오류를 보존했고 중단 구간은 `lab_audit`의 `recover`로 기록했다. 경보 임계값이나 정책 검증을 끄지 않았다. 기존 사용자 관찰 시계를 재시작하지 않으며, 중단 구간이 있는 결과는 참고용이다. 분석의 `operational_recoveries`와 어드민 상세에 이 이력을 표시하고 품질 통과로 판정하지 않는다.

### 배포 전후 확인

작업 전 실행 중인 실험을 확인하고 정책에 영향을 주지 않는 변경도 파일 전체 검증 범위에 포함되는지 확인한다. 후보 코드 적용 후 재시작 전에 다음 읽기 전용 검증을 수행한다.

```sh
python -m app.jobs.check_experiment_integrity
```

재시작 후에는 유지할 실험을 명시해 정책 검증값과 실행 상태를 함께 확인한다. ID와 키는 현재 어드민에서 확인한다.

```sh
python -m app.jobs.check_experiment_integrity --expect-lab-id <ID> --expect-button-key <KEY>
```

기본 어드민의 공통 목록 및 상세 UI는 다음 도구로 검증한다. `playwright-core`와 Chromium을 사용할 수 있는 환경에서 실행하며 `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ADMIN_BASE_URL`, 필요 시 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`을 비공개 환경변수로 전달한다. 실제 주소·인증정보를 코드나 실행 결과에 기록하지 않는다.

```sh
node scripts/verify_experiment_admin.cjs --expect-running-name "<유지할 실험 이름>"
```

이름 옵션은 여러 번 지정할 수 있다. 도구는 데스크톱·모바일의 공통 목록에서 실행 상태를 확인하고 각 실험의 상세·5개 탭·새로고침·직접 상세 주소·목록 복귀를 검사한다. 운영 상태 변경 버튼은 누르지 않는다. 정책 검증값 불일치, 유지할 실험의 중단, 목록 누락, 유형별 상세 연결 실패가 있으면 완료로 보고하지 않는다.

### 버튼 실험 모집 가능성 재검토 (2026-10-14)

기존 적격 버튼 유입을 중복 제거한 결과 7일 1,649명, 28일 2,017명으로 3,534명 가정은 운영 목표에서 폐기했다. [데이터 기반 개정 계획](menu-button-experiment-design.md)에 따라 7일 고정·예상 1,200명의 사후 탐색으로 변경한다. 원래 계획과 배정은 보존하며 신규 시작 스크립트는 미검토 기본값으로 실험을 생성하지 못하게 했다. 공통 어드민에서 예상 모집/마감/개정 이력과 탐색용 Fisher/CI를 확인한다. `complete_due_timeboxes`는 명시적으로 시간 제한된 버튼 실험만 처리하며 기존 lab 실험에는 적용되지 않는다.

이후 실험 설계와 변경은 [cnubot-experiment-review 스킬](../skills/cnubot-experiment-review/SKILL.md)을 필수 적용한다.

### 공통 목록 표시 기준

실험 저장소와 관계없이 `running`은 ‘모집 중’, `paused`는 ‘모집 일시중지’로 목록·필터·상세에서 동일하게 표시한다. 목록은 현재 참여자, 모집 계획, 관찰 완료 인원, 모집 마감을 서로 다른 열로 제공한다. 개인별 관찰창이 없는 버튼 실험의 관찰 완료 칸에는 마감 시각 대신 ‘개인별 관찰창 없음’을 표시한다. 목표 인원은 종료 조건, 예상 인원은 참고치로 구분하며 예상치에 참여자/목표 비율 표시를 붙이지 않는다. 배정 균형만 정상인 경우 전체 데이터 품질을 ‘확인됨’으로 표시하지 않는다.

### 중단 A/A의 제한적 품질 승인

기본 계측 점검의 부분 승인은 `lab_audit.basic_quality_approval`의 `scope=basic_instrumentation`, `formal_pass=false`로 기록한다. 공통 API의 `quality_review`는 이 감사 기록을 읽어 목록·상세에 승인 범위와 보류 항목을 표시한다. 분석 결과·실험 상태·고정 계획을 바꾸지 않고 정식 A/A 완료 게이트에도 사용하지 않는다. [부분 승인 근거](aa-stopped-quality-review.md)를 참고한다.
