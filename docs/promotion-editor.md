# 상품·버튼 관리

관리자 화면: `/admin/recommendations` (기존 관리자 인증 사용)

1. 토스 공유 문구 전체 또는 `https://toss.im/_m/...` 링크를 붙여넣고 **상품 불러오기**를 누릅니다.
2. 상품명, 상품 버튼 문구, 설명, 이미지를 확인합니다. ↑ ↓로 순서를 바꾸고 체크박스로 숨길 수 있습니다.
3. **고정 상품 모드**를 켜고 학식 메뉴 버튼 / 스케줄 퀵리플라이 문구를 지정합니다.
4. **저장하고 적용**을 누르면 다음 챗봇 응답부터 반영됩니다.

자동 추천으로 되돌려도 고정 상품 목록은 보관됩니다. 문구를 직접 입력하면 두 모드 모두 그 문구를 사용합니다. 빈 문구는 자동 모드에서 기존 시간대별 문구, 고정 모드에서 일반 추천 문구를 사용합니다. 노출 상품은 최대 6개이며 숨김 포함 30개까지 보관합니다.

공유 페이지에서 상품 옵션 ID(`tacaItemId`)를 확인하고 토스 상세 API로 판매가·정가·할인율·품절 여부를 조회합니다. 정상 상품은 기존 자동 추천과 같은 commerceCard로 노출합니다. 원래 제휴 링크와 관리자가 지정한 순서·문구는 유지합니다. 가격 조회 실패 또는 품절 시 가격 확인/품절 안내 카드로 표시하며 오래된 가격을 최신 가격처럼 보여주지 않습니다.

미리보기는 `/admin/promotion-settings/preview`에서 실제 챗봇과 같은 응답 생성 함수를 사용합니다. 상품 이미지, 제목, 판매가, 취소선 정가, 할인율, 설명, 버튼을 표시하며 상품명에 순서 번호를 붙이지 않습니다. 기기별 글꼴과 줄바꿈은 다를 수 있습니다. 상품 상세는 최대 1시간 캐시하며 **가격 새로고침**으로 즉시 재조회합니다. 미리보기에서 설정을 저장하거나 상품 클릭 이벤트를 기록하지 않습니다.

제휴 수수료 안내는 상품 앞에 표시합니다. 챗봇 응답 지연을 제한하기 위해 가격 조회가 3.5초를 넘으면 가격 확인 안내 카드로 응답합니다. 상세 조회는 최대 3개씩 동시에 수행하며 지정한 순서는 유지합니다.

## 저장 및 추적

- `${MENU_DATA_DIR}/promotion_settings.json`에 원자적으로 저장합니다. 기본 경로는 `/data/menus/promotion_settings.json`이며 기존 Compose의 `./data` 볼륨에 보존됩니다.
- 파일 잠금과 revision 비교로 동시 편집 덮어쓰기를 방지합니다. 충돌 시 새로고침해야 합니다.
- 모든 관리 API에 기존 HTTP Basic 인증을 적용하고 쓰기/조회 요청 중 POST·PUT은 사용자 지정 헤더를 요구합니다. 인증 정보는 브라우저 코드에 포함하지 않습니다.
- 고정 모드에서는 추천 후보 조회와 정렬을 호출하지 않습니다. 집계 오류 때문에 다른 상품으로 대체하지 않습니다.
- 상품 키는 공유 URL의 해시로 안정적으로 유지됩니다. 노출에 순서·모드·설정 revision·상품 버튼 문구를 기록합니다. 서명된 클릭 URL에 당시 상품명·버튼 문구·revision을 포함해 이후 설정 변경에도 당시 기준으로 추적합니다.
- 기존 분석과 호환하기 위해 구매 페이지 이동 이벤트 이름은 `commerce_card_click`을 유지합니다.

## 인사이트 해석

2026-09-10 수정: 날짜 경계를 한국 시간으로 명시하고, 앞 단계 이후 발생한 첫 유효 이벤트를 차례로 찾아 퍼널을 계산합니다. 기존의 단계별 독립 MIN은 먼저 클릭하고 나중에 재진입한 사용자를 잘못 제외하거나 단계별 인원을 역전시킬 수 있었습니다.

상단 퍼널은 선택 기간 안에 순서대로 행동한 사용자만, 상세 표는 선택 기간 안의 전체 이벤트 사용자를 집계합니다. 응답에 포함된 버튼/상품을 노출로 기록하며 실제 화면 열람을 측정한 것은 아닙니다. 따라서 회전 문구별 CTR은 시간대와 사용자 구성의 영향을 받으며 무작위 A/B 실험 결과로 해석하면 안 됩니다.

우선 대표 상품 1~3개를 고정하고 실제 상품을 설명하는 진입 문구를 유지합니다. 메뉴 버튼과 퀵리플라이는 따로 비교하고, 진입 CTR뿐 아니라 노출 사용자 대비 상품 링크 클릭 사용자 비율도 확인합니다. 가격·할인·무료배송 문구는 해당 상품의 실제 조건 확인 후 입력합니다. 현재 클릭 수가 적어 특정 문구나 상품을 승자로 판정할 근거는 부족합니다.
